# Live Audience Interaction (лёгкая альтернатива Slido)

Аудитория отправляет вопросы с телефонов — они мгновенно появляются на большом экране.
Вопрос можно подписать своим именем и приложить фото — и то и другое увидят все на экране.

## Стек

- **Backend:** Node.js, Express, Socket.IO, `qrcode-generator` (QR рисуется локально, без внешних сервисов)
- **Frontend:** HTML5, Tailwind CSS (CDN), Vanilla JS (Socket.IO client)

## Запуск

```bash
npm install
npm start
```

## Автозапуск: одна команда — готовая ссылка

```bash
npm run share
```

Скрипт `share.js` сам поднимает туннель, получает внешний адрес, запускает сервер
с этим адресом в `PUBLIC_URL`, открывает экран презентации в браузере и печатает
готовую ссылку с QR прямо в консоли:

```
  ================================================================
   ССЫЛКА ДЛЯ ГОСТЕЙ:  https://4ea6992c87b26a.lhr.life
  ================================================================
```

Туннель берётся из того, что доступно: `localhost.run` через встроенный в Windows 10/11
`ssh` (без регистрации и загрузок) → `cloudflared` → `ngrok`. Каждый запуск выдаёт новый
адрес; его можно смело отправлять в чат — ссылка открывается с любого телефона и с любым
интернетом, а QR-код на экране обновится сам.

Для Windows есть файл `start.bat` — двойной клик: при необходимости поставит зависимости
и запустит всё то же самое в одном окне.

Полезные варианты:

```bash
npm run share -- --lan     # без туннеля, только локальная Wi-Fi сеть
NO_OPEN=1 npm run share    # не открывать браузер автоматически
```

### Как остановить

- В окне запуска: **Ctrl + C** — сервер и внешний туннель выключаются вместе,
  публичная ссылка сразу перестаёт работать.
- Если окно уже закрыто, а сервер продолжает работать (порт 3000 занят):
  двойной клик по `stop.bat` — он найдёт процесс на порту 3000 и закроет ssh-туннель.
- Быстрая проверка: пустая строка в ответ на
  `Get-NetTCPConnection -LocalPort 3000 -State Listen` означает, что всё выключено.

## Адреса

| Страница | Кому | URL |
| --- | --- | --- |
| Участник | телефоны | `http://<IP-компьютера>:3000/` |
| Экран презентации | ТВ / проектор | `http://<IP-компьютера>:3000/screen` |

IP-адрес для телефонов печатается в консоли при запуске и показывается в подвале экрана презентации.
На экране есть **QR-код** (правая панель) — гостям достаточно навести камеру телефона, вводить адрес
руками не нужно. Кнопка «Скрыть QR» в подвале убирает панель, если она мешает.
У каждой карточки с вопросом есть кнопка **✕** (появляется при наведении) — она убирает
**только один** вопрос у всех клиентов, не трогая остальные.
**Клик по карточке** открывает вопрос на весь экран крупным шрифтом — его видно даже с последних
рядов (закрыть: клик по фону, кнопка ✕ или Esc; с клавиатуры карточка открывается клавишей Enter).
Если участник указал имя и приложил фото — они показываются в карточке и в увеличенном виде.

## Проведение мероприятия: как подключаются гости

### Вариант A. Общий Wi-Fi (основной сценарий)

1. Компьютер ведущего и телефоны гостей — в одной Wi-Fi сети.
2. Откройте `/screen` на проекторе: QR-код и ссылка заполнятся автоматически
   (например, `http://192.168.1.50:3000/`).
3. Гости сканируют QR-код камерой — и сразу задают вопросы.

> Если телефон не открывает страницу, разрешите Node.js доступ в брандмауэре Windows
> для **частных** сетей (запрос появляется при первом запуске).

### Вариант B. У гостей мобильный интернет (4G/5G)

Тогда локальный IP не подойдёт — нужен туннель. Просто запустите приложение командой:

```bash
npm run share
```

Внешняя ссылка поднимется и подставится автоматически — в консоли, в подвале экрана
и в QR-коде. Настраивать ничего не нужно. Ручные варианты, если так удобнее:

```bash
npx ngrok http 3000                            # нужен бесплатный аккаунт ngrok
winget install --id Cloudflare.cloudflared     # затем: cloudflared tunnel --url http://localhost:3000
```

Сервер сам определяет внешний адрес по заголовкам `X-Forwarded-Proto` / `X-Forwarded-Host`,
поэтому и в подвале, и **в QR-коде** сразу появится ваша внешняя ссылка (например,
`https://abc-123.ngrok-free.app`). Ссылка откроется у любого человека с любым интернетом.

Чтобы задать адрес вручную (свой домен, обратный прокси, фиксированный субдомен ngrok):

```bash
# Linux / macOS
PUBLIC_URL=https://event.example.com npm start

# Windows PowerShell
$env:PUBLIC_URL="https://event.example.com"; npm start
```

## HTTP API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/` | страница участника (телефон) |
| `GET` | `/screen` | экран презентации: лента + QR-код |
| `GET` | `/api/info` | `{ port, participantUrl }` — адрес для гостей |
| `GET` | `/api/qr.svg?size=512` | QR-код этого адреса (SVG, генерируется локально) |

## Socket.IO API

| Событие | Направление | Назначение |
| --- | --- | --- |
| `send-message` | клиент → сервер | отправить вопрос `{ text, name?, photo? }` (текст — до 200 символов, имя — до 40, фото — data-URL картинки), ack: `{ ok, id }` или `{ ok: false, error }` |
| `new-message` | сервер → все | новое сообщение `{ id, text, name, photo, createdAt }` (`name`/`photo` — пустая строка, если участник их не указал) |
| `init-messages` | сервер → клиент | история сообщений при подключении |
| `clear-all` | клиент → сервер | очистить экран у всех (модерация) |
| `messages-cleared` | сервер → все | экран очищен |
| `delete-message` | клиент → сервер | удалить **один** вопрос по `id`, ack: `{ ok, id }` или `{ ok: false, error: 'not-found' }` |
| `message-deleted` | сервер → все | вопрос удалён — карточка убирается у всех |

## Ограничения (встроенная защита)

- текст обрезается до **200 символов**, лишние пробелы схлопываются; без текста сообщение принимается только при наличии фото;
- имя обрезается до **40 символов**, лишние пробелы схлопываются, на телефоне подставляется из прошлого визита (localStorage);
- фото сжимается прямо на телефоне: canvas → JPEG, длинная сторона до **640 px**, data-URL до ~180 КБ;
- сервер принимает только фото в виде data-URL `image/png|jpeg|webp|gif` (до 300 000 символов) — небезопасные и слишком большие вложения молча отбрасываются, сообщение при этом не теряется;
- серверный антиспам: не чаще одного сообщения в **700 мс** с одного подключения;
- клиентский дебаунс кнопки: **1.5 с**;
- в памяти хранится последние **100** сообщений (вместе с именем и фото — для позднего подключения экрана);
- XSS исключён: и текст, и имя вставляются через `textContent`, фото — только после проверки data-URL.

## Тест

```bash
npm start            # в одном терминале
npm test             # в другом (требуется Node 22+, используется встроенный WebSocket)
```

Тест проверяет реальный обмен через Socket.IO: доставку сообщения на экран, историю для нового
подключения, ack, антиспам, обрезку до 200 символов, имя (пробелы и обрезка до 40 символов),
фото (валидный data-URL проходит и сохраняется в истории, небезопасный отбрасывается, одно фото
без текста тоже можно отправить), удаление одного вопроса, окно увеличения вопроса по клику и очистку экрана. Дополнительно проверяются
сценарии мероприятия: определение внешнего адреса за туннелем (`https://…ngrok-free.app`),
переопределение адреса через `PUBLIC_URL` и QR-код — SVG, структура матрицы и **реальное
считывание независимым декодером** `jsQR` (dev-зависимость).
